## 1. الملخص التنفيذي (Executive Summary)

### 1.1 الرؤية
أن نصبح المنصة العربية الأولى التي تحول أي وكالة تسويق من "شغل يدوي" إلى "نظام آلي ذكي" يضاعف إنتاجية الفريق 3x دون أي تكلفة شهرية.

### 1.2 المشكلة
وكالات التسويق العربية (خاصة الصغيرة والمتوسطة) تواجه:
- **تأخيرات تشغيلية 7-21 يوم** في كل مرحلة (استلام العميل → البحث → الإبداع → الإطلاق)
- **70% من وقت الفريق** يذهب في مهام يدوية (تقارير، نسخ إعلانات، تحليل)
- **حرق ميزانيات** بسبب التأخر في اكتشاف المشاكل
- **صعوبة التوسع** - الموظف الواحد يخدم 3-5 عملاء فقط

### 1.3 الحل
منصة موحدة (All-in-One) بـ 7 وحدات + ذكاء اصطناعي مجاني، تقلل وقت العمل 70% وتكشف المشاكل فوراً.

### 1.4 نموذج الربح
- **مجاني تماماً** (Open Source MIT) - يحقق قيمة عبر:
  - بناء مجتمع
  - خدمات استشارية اختيارية
  - استضافة مُدارة (مدفوعة) للشركات الكبيرة

## 2. أهداف المنتج (Product Goals)

### 2.1 الأهداف الأساسية (KPIs)

| المؤشر | الهدف في 6 أشهر |
|--------|-----------------|
| عدد التحميلات على GitHub | 1,000+ |
| عدد الوكالات المستخدمة | 100+ |
| متوسط وقت Onboarding | < 24 ساعة (كان 7 أيام) |
| عدد العملاء الممكن إدارتهم للفرد | 12-15 (كان 3-5) |
| تقييم المستخدمين (NPS) | > 50 |

### 2.2 مبادئ التصميم
1. **مجاني 100%** - لا توجد ميزات مدفوعة مخفية
2. **يعمل Offline** - الذكاء الاصطناعي يمكن أن يكون محلي بالكامل
3. **RTL First** - مصمم للسوق العربي من اليوم الأول
4. **Self-hostable** - أي شخص يقدر ينشره على سيرفره
5. **مفتوح المصدر** - الكود شفاف وقابل للتدقيق

## 5. المتطلبات غير الوظيفية (Non-Functional)

### 5.1 الأداء
- **وقت تحميل الصفحة:** < 2 ثانية
- **استجابة API:** < 500ms
- **دعم مستخدمين متزامنين:** 50+ على سيرفر واحد

### 5.2 الأمان
- **HTTPS إجباري** في الإنتاج
- **CSRF Protection** على كل forms
- **API Rate Limiting** (100 طلب/دقيقة/مستخدم)
- **Environment variables** لكل secrets
- **Audit log** لكل العمليات الحساسة

### 5.3 التوفر (Availability)
- **Uptime:** 99.5% (self-hosted)
- **Backup يومي** تلقائي لقاعدة البيانات
- **Recovery time:** < 1 ساعة

### 5.4 قابلية التوسع (Scalability)
- معماري يدعم Multi-tenant
- فصل Frontend / Backend
- Queue system للمهام الثقيلة (المرحلة 2)

### 5.5 التوطين
- **اللغة:** العربية (RTL) كل الواجهات
- **العملة:** افتراضياً SAR، قابل للتغيير
- **التاريخ:** تقويم هجري + ميلادي
- **الأرقام:** أرقام عربية-هندية اختيارية

## 6. البنية التقنية (Technical Architecture)

### 6.1 الـ Stack

```
┌─────────────────────────────────────┐
│       Frontend (Next.js 14)         │
│   - React 18 + TypeScript           │
│   - Tailwind CSS                    │
│   - Server Components               │
└──────────────┬──────────────────────┘
               │ REST / Server Actions
┌──────────────┴──────────────────────┐
│        Backend (Next.js API)        │
│   - Route Handlers                  │
│   - Server Actions                  │
│   - Auth (NextAuth - مرحلة 2)       │
└──────────────┬──────────────────────┘
               │
       ┌───────┴───────┐
       │               │
   ┌───┴───┐      ┌────┴─────┐
   │Prisma │      │  AI Layer │
   │ + DB  │      │  (3)     │
   └───────┘      └──────────┘
```

### 6.2 مخطط قاعدة البيانات

**20 جدول رئيسي** موزعين على الوحدات:
- `Client` + `BrandAsset` + `Contract`
- `Persona` + `Competitor` + `CompetitorAd` + `Trend`
- `Template` + `Content`
- `Product` + `StoreConnection`
- `Campaign` + `Ad`
- `Metric` + `Insight` + `Report`
- `Workflow` + `Task` + `Setting`

### 6.3 طبقة AI (3 مزودين، Fallback تلقائي)

```
طلب AI → Ollama (محلي) → OpenRouter → HuggingFace → رسالة خطأ
```

## 10. الخلاصة
